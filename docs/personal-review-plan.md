本计划对应[个人版需求与验收场景](personal-review-requirements.md)，术语见[CONTEXT.md](../CONTEXT.md)。

**新增接口的约束与剩余验证**：

- `ReviewStorage.open(vaultRoot, dataRoot)` 要求调用方显式提供已存在的设备本地目录。已检查真实路径在 vault/Git 工作目录之外；无法自动识别所有云同步软件，实际目录选择仍是宿主集成门禁。
- 文件是设备本地明文认可记录，不宣称加密；没有写入令牌或 GitLab 内容缓存。
- `beginInitialization` → `initializeDocument` → `finishInitialization` 保存首次初始化进度。存储不会自行读取 vault 原稿；宿主必须提供经过变化检查的初始内容，不能在冲突或中断后偷偷认可新读到的版本。
- 原认可记录与撤销记录随单个文档一起提交。失败时不发布新认可状态；一旦开始提交已核对的决定，完成该决定的发布，不在保存之后重新读入更晚的正文。
- `close()` 等待已排队存储操作结束并使文档操作失效。真实宿主退出可能不等待异步卸载，必须在宿主接入阶段单独验证。
- 当前不自动夺取残留写锁。异常退出留下的锁会阻止写入；安全诊断/恢复流程必须在实际安装前补齐验证，不能让用户盲删正在使用的锁。
- 在线重命名、GitLab 文档链接映射和凭证尚未进入该存储格式；不把底层存储通过等同于整个阶段 2 或 A01–A28 宿主验收完成。

## 3. 模型与模块划分

### 3.1 认可内容不是“已看过”标记集合

设当前正文为 `C`、认可内容为 `B`、参考版本为 `R`：

- 待审差异：`diff(B, C)`。
- 参考差异：`diff(R, C)`。
- 接受一项：只把该项从 `C` 纳入 `B`，`C` 不变。
- 拒绝一项：只把该项在 `C` 中恢复成 `B` 的内容，`B` 不变。
- 接受本文全部：认可本次已经核对的 `C` 快照，不在异步保存后重新读取并认可更晚的正文。
- 撤销认可：恢复最近一次接受前的 `B`，当前 `C` 不变。

不靠隐藏 diff 卡片表示认可。认可修订号和正文快照必须进入操作身份，以防在新状态下执行旧按钮。

### 3.2 少量明确的模块

以下文件名是实施建议，可因合理的代码组织调整；职责不应混淆：

| 模块 | 小接口所承载的行为 | 验证方式 |
| --- | --- | --- |
| `review.ts` | 取得审阅快照，接受一项/本文全部，准备拒绝，撤销认可；校验作用范围与修订号 | 通过真实接口验证状态转移、错位和并发，不直接修改内部 Map 来造成功能 |
| `review-storage.ts` | 读取与持久化一个 vault 的初始化状态、认可记录、最后一次接受的撤销数据、链接对应关系 | 用临时目录验证重启、写入失败、恢复和隔离；明确单写入者规则 |
| 现有 `diff.ts` / `store.ts` | 计算与展示特定来源快照；保留异步过期防护 | 保留现有回归测试，增加来源切换与认可来源测试 |
| `gitlab.ts` | 将明确配置的 GitLab 文件链接解析并读取为带提交标识的参考快照 | 注入受控请求与凭证读取接口，用虚构响应验证，不把网络协议写进面板 |
| 现有 `main.ts` / `panel.ts` / `editor.ts` | 宿主事件、编辑器写入、用户交互 | DOM/宿主替身测试加隔离 vault 实测 |

普通设置与敏感状态分开。认可正文需要全文或等价的可恢复表示，不能只存 hash；当前最新正文通常不必再持久化一份，因为来自 vault/编辑器。

审阅与参考对比可以复用 `DiffStore` 的能力，但不能只有一个以文件路径为键、来源不明的缓存。快照至少区分文件、模式、来源身份、版本身份和当前正文。不要用假的 HEAD 提交号冒充认可版本。

## 4. 阶段 0：验证存储、兼容性与请求能力

这一阶段只做小范围、可丢弃的技术验证，不以未经验证的假设开展持久化或携带令牌的请求。

### 4.1 状态存储

- 确定设备本地、vault 外的实际存储位置，按规范化 vault 身份隔离；校验位置不落入个人仓库/同步目录。无法保证时应说明并要求选择合适位置，不悄悄退回 `.obsidian/plugins/.../data.json`。
- 验证全 vault 认可内容的容量、分文件读取、串行写入、失败恢复。不能把所有正文作为一个 `localStorage` 值，也不能每次击键重写全 vault。
- 定义一个 vault 的单写入者规则；多窗口可以共用同一实例，第二个独立实例不得无保护覆盖认可记录。
- 通过临时文件替换等方式提交完整状态，实际验证 Windows 行为，不凭函数名宣称原子性。
- 首次初始化完成标志、初始文件集合及逐文件进度可恢复。有初始化标志但缺少记录、版本不兼容、解析/读取失败等情形必须报错，不能当作首次启动。
- 若所有数据连同初始化标志都被外部清除，无法仅凭正文辨认过去的认可状态；记录此限制，提供显式恢复/重新初始化说明，不承诺自动找回。
- `.gitignore` 不是隔离或保密保证；还要检查真实落盘位置。

### 4.2 宿主版本和凭证

本地安装的 Obsidian SDK 为 1.13.1，但当前 [manifest.json](../manifest.json) 的 `minAppVersion` 是 **1.8.0**：

- `App.secretStorage` 及其方法声明为 **1.11.4+**。
- `App.loadLocalStorage` / `saveLocalStorage` 声明为 **1.8.7+**。
- SDK 中有接口不等于当前宿主支持，必须使用版本/能力保护。
- 首选支持的宿主凭证能力；确认其实际存储和同步行为后再承诺长期保存。旧宿主可使用仅内存令牌，不能明文回退到普通设置。
- 不因测试替身具有新 API，就绕过真实宿主兼容性验证；暂不提高最低版本。

### 4.3 网络控制

`requestUrl` 是宿主提供的无 CORS 限制请求接口，但本地 SDK 的 `RequestUrlParam` 未公开重定向控制或 `AbortSignal` 参数：

- 不能直接声称它能阻止跨来源重定向、真正取消网络请求或严格限制响应下载大小。
- 在无真实令牌的隔离环境验证请求/重定向行为；凭证只允许发往明确配置的 origin（含端口）和 GitLab API 路径。
- 如果传输层无法证明携带凭证时不向非授权来源转发，先阻止该路径并提出可验证的替代传输设计，不静默降级。
- 逻辑取消与网络取消区分：即使请求无法终止，也必须丢弃取消后的返回值。
- 默认 HTTPS，不为“连不上公司服务器”自动关闭证书验证；如实例需要特殊证书或协议，单独确认。

**通过标准**：有可验证的安全存储和请求路径，或明确禁用不满足条件的能力。无条件把 token 写入设置、跨来源转发凭证、偷偷提高宿主版本，都不是可接受的绕过方式。

## 5. 阶段 1：认可状态与单项操作

**目标**：先建立与 Obsidian UI、Git 和网络无关的核心审阅行为。

1. 为已知 `B`、`C` 建立快照与修订号，复用现有连续改动项粒度。
2. 如需要，在 `LineChange` 增加旧侧坐标；纯插入、纯删除和换行边界均可定位，不能直接把当前侧行号应用到旧正文。
3. 实现逐项接受、接受本文全部和撤销最近一次认可。显示上下文不属于操作目标。
4. 将还原编辑准备与具体来源校验分开，保持现有 HEAD 还原校验不退化；审阅拒绝不调用 Git。
5. 所有操作针对已经展示并核对的快照；接受保存失败不得先展示为已认可并报成功。

**测试**：新增 `tests/review.test.ts`；扩展 diff/revert 测试。覆盖 A06–A13、A15、A25，特别是多个独立改动、前方增删造成的行号偏移、空文件、CRLF 与末尾换行。

**阶段门禁**：现有 144 项仍通过；新增操作测试通过；尚未接入 UI 的能力只算核心模块完成。

## 6. 阶段 2：持久化与全 vault 生命周期

**目标**：重启不丢待审，未打开过的文件也保有认可起点。

1. 添加版本化状态格式；与现有普通设置读取兼容，不把已有的 0.3.0 设置误认成审阅状态。
2. 在宿主完成初始文件发现后建立第一次文件集合，持久化初始化进度；区分启动时的 `create` 通知与真正的新文件，不能仅靠一次事件判断。
3. 读取初始正文时考虑活跃编辑器的未保存内容；读取过程中有冲突则标明未完成，不以新的正文重试并自动认可。
4. 注册全 vault Markdown 的 create/modify/rename/delete；初始集合之后的新路径使用空白认可内容。
5. 已有记录的文件在启动时继续沿用认可内容；关闭期间新增路径同样全篇待审。
6. 文档关闭只释放可重算的展示缓存，不删除认可、撤销或链接记录。只为当前查看的文档计算完整 diff，不全 vault 定时执行 Git/网络请求。
7. 已确认的在线文件/目录重命名迁移记录；未知离线移动保守地当作新路径。删除后不重建文件，也不直接抹掉历史认可记录。
8. 接受与撤销走串行持久化及修订校验；在运行中及时保存，不依赖 unload 才刷盘。

**测试**：新增 `tests/review-storage.test.ts` 和生命周期集成测试，覆盖 A01–A05、A14、A26、A27。包含初始化中断、文件读失败、配额/写失败、损坏状态、迟到事件和多实例写入竞争。

**阶段门禁**：使用临时目录模拟两次进程生命周期；不在用户 vault 做故障注入。

## 7. 阶段 3：来源快照与两个 Tab

**目标**：把审阅和 HEAD 对比接入同一个面板，先不接 GitLab 网络。

1. 给通用比较快照增加来源与版本身份；分别维护审阅和版本对比状态。
2. 新增 Tab 和明确来源文案，默认审阅；当前文档切换同时刷新两模式的目标，但不清理持久化认可内容。
3. 审阅 Tab 提供接受此项、拒绝此项、接受本文全部、撤销认可；没有待审时显示“无待审改动”，不能写“与 HEAD 一致”。
4. HEAD Tab 保留原对比及确认还原，标为“从 HEAD 还原”；动作不能更新认可内容。GitLab 不新增本地恢复按钮。
5. 编辑器标记、状态栏、前后导航跟随当前模式。全插件当前模式保持明确，不同时叠加两套标记。
6. 模式/文件/来源变化取消旧确认操作；暂存选区期间继续保护复制并禁用旧动作。
7. 审阅拒绝保持单次编辑器事务、取消和过期检查；编辑器尚未与外部写入同步时拒绝操作而非覆盖。
8. 不改写现有命令 ID 的 HEAD 含义；新增审阅入口，现有 HEAD 命令明确进入版本对比。

**测试**：扩展 panel/editor/revert-modal/i18n/settings 测试。覆盖 A07、A08、A12、A13、A16–A18、A25、A28；验证 Tab 键盘行为、焦点、空态以及不同来源的错误隔离。

**阶段门禁**：审阅在 Git 不可用时可用；全部原有安全与交互回归通过。

## 8. 阶段 4：GitLab 文件链接读取

**目标**：添加一个有明确权限和版本身份的远端参考来源，不扩展成仓库管理工具。

1. 配置公司 GitLab 实例与只读凭证引用；只在用户发起读取或刷新时访问网络，不因启动、切换文件或每次编辑而自动请求远端。
2. 保存每篇文档的 GitLab 链接；不同本地与远端路径无需匹配。公司链接和凭证不进入普通可同步设置。
3. 解析仓库文件链接；处理子组、中文与空格路径、URL 编码、查询/行号锚点，以及自建实例可能的路径前缀。
4. `/-/blob/` 之后的引用可能包含 `/`，不能简单认定第一个路径段就是分支。解析必须得到明确的项目、引用和文件路径；有歧义时核实或明确报错，不能悄悄对比错误文件。
5. 通过只读 Files API 获取内容与实际提交标识，验证响应结构、文本编码、路径与大小；不能把登录页/错误 JSON 当正文。
6. 一次成功读取形成固定参考快照；本地修改仅重算 diff，手动刷新成功后才替换参考快照。
7. 响应身份包含本地文档、链接/凭证配置版本和请求代数，过期结果不落到新目标。参考内容无需持久化，重启后显示“尚未读取”。
8. 读取失败保留清晰错误；如仍显示旧快照，必须标明它是上次成功结果，不能声称刷新成功。认可内容和正文始终不受影响。

**测试**：新增 `tests/gitlab.test.ts`，以及面板来源切换测试。覆盖 A19–A24；请求夹具使用 `gitlab.example.com` 和虚构文件，包含 401/403/404、登录 HTML、超限、TLS/超时错误、跨来源重定向和乱序响应。

**阶段门禁**：阶段 0 的凭证/传输安全验证必须已经通过。受控测试通过不等于公司真实实例联通；真实验证只使用用户在本地配置的凭证。

## 9. 阶段 5：集成与个人版交付

### 自动门禁

```bash
npm run check
```

该命令包含 lint、测试、类型检查、构建和本地 release 产物一致性检查，**本身不推送或发布**。不设置发布标签、不调用 release workflow。若依赖不变，不无故重写 lockfile。

### 隔离宿主验证

用虚构文档建立测试 vault，执行需求中的 A01–A28。每条记录为“通过 / 失败 / 阻塞”，不能以 mock 通过覆盖真实权限和宿主验证的缺失。

重点实测：

- 源码编辑、实时预览、弹出窗口、文本复制和导航。
- 多文档、未打开文档、外部工具写入、重启与关闭期间的变化。
- 初始化进度、状态损坏与保存失败时的可恢复行为。
- 部分接受、接受本文全部、撤销认可和编辑器撤销拒绝。
- 两个 Tab 的来源隔离，HEAD 还原之后重新出现的待审差异。
- GitLab 私有认证、实际提交标识、刷新与过期响应；无法访问公司实例则明确列为未验证，不把它记为通过。
- 存储位置和所有产物中没有令牌、真实公司文档或远端缓存泄漏。

### 交付材料

- 分支 diff、实际完成的阶段和残余风险。
- 自动测试结果与隔离宿主验收记录。
- 本地构建产物与手工安装/回退说明；是否安装到实际 vault 另行由用户决定。
- 审阅状态备份与兼容性说明：禁用插件或切回旧版不能删除个人版的设备本地认可记录；旧版不会理解这些记录。

不为个人版更新公开演示、触发社区发布、删改旧版本标签或把测试结果表述为线上安全认证。

## 10. 实施时的停止条件

遇到以下问题，应保留证据并说明，不靠扩大权限或自动认可消除提示：

- 把可检测的状态缺失、损坏或读取失败，当作首次初始化而自动认可当前正文。
- 无法保证持久化失败时不报成功，或多实例可能相互覆盖。
- 无法保证私有 GitLab 凭证只发往明确授权的实例。
- 需要将公司数据放入个人仓库同步范围、降低 TLS 校验、提升宿主最低版本或改变用户已经确认的操作方式。
- 任何确认后写正文的路径缺少取消、过期检查或编辑器撤销能力。

只有真正改变使用方式或权限的取舍才再次询问用户；普通文件组织和测试实现不再扩大需求讨论。
