# 测试与发布检查

## 自动化验证

```bash
npm ci
npm run check
npx tsc --noEmit --noUnusedLocals --noUnusedParameters
npm audit
```

`npm run check` 执行测试、类型检查、生产构建及发布文件校验。目前有 96 项测试，覆盖：

| 范围 | 主要检查 |
| --- | --- |
| 差异计算 | 增删改、空文档、Unicode、CRLF、末尾换行、上下文合并、零上下文、删除定位、体积限制 |
| Git 读取 | HEAD/暂存区/工作区区分、特殊路径、未跟踪文件、无首次提交、嵌套仓库、worktree、冲突、错误处理、只读检查 |
| 快照管理 | 缓存、并发去重、过期结果丢弃、错误恢复、卸载清理、展示设置不重复读取 Git |
| 编辑器与导航 | CodeMirror 行标记、实时预览块级部件、选区末端、焦点隔离、精确行映射、配对滚动 |
| 行配对与高亮 | 相似行对齐、插入行、字素边界、空白符、超限回退、源码完整性 |
| 选择复制 | 部分选择、跨高亮节点、多行与空行、原始空白、排除辅助文字、面板外选择不拦截 |
| 局部还原 | 保留其他块和上下文、换行、零上下文纯删除、取消与过期保护；200 组混合变更在 4 种上下文下还原 |
| 设置 | 默认值、旧配置兼容、独立开关、数值边界、无效输入 |

Git 测试只在系统临时目录创建自己的仓库，不操作开发者的笔记仓库。发布校验检查版本一致、桌面端声明、清单格式、构建副本、许可声明及双语 README 链接。

## 宿主验证范围

已在 Windows / Obsidian 1.13.7 验证：

- 源码编辑与实时预览的标记、双向定位、焦点保持及首尾循环。
- 旧新行相邻、联合定位、受限视口滚动，以及复制原始 Markdown。
- 原生设置控件的字号、上下文、显示开关、联动开关和刷新参数。
- 原生 Markdown 渲染器在已有差异快照时不添加阅读正文标记。
- 隔离的原生编辑器事务能只还原目标块，撤销/重做与之前的输入保持独立。
- 确认弹窗的取消行为；异步取消和过期拒绝另有自动化覆盖。

宿主测试不使用真实笔记执行还原，不调用系统剪贴板写入，也不覆盖用户配置。完整文件保存链路、其他平台、旧版 Obsidian 和第三方主题仍应在独立测试 vault 中验收。

## 手动回归建议

使用独立测试 vault，关闭可能自动格式化测试内容的第三方插件：

1. 建立测试 Git 仓库，提交包含标题、列表、表格、Callout、代码块、YAML 和中文的文档。
2. 修改多处内容；检查源码编辑、实时预览的标记及面板统计，确认阅读正文无标记。
3. 检查配对展示、左右导航、长行、窄侧栏、首尾循环和键盘操作。
4. 选择复制部分文字、多行及空白符，核对粘贴后的原始内容。
5. 还原其中一块，确认其他修改保留、保存正确、撤销/重做正确。测试取消，以及确认期间编辑、切换模式或提交新 HEAD。
6. 检查空文件、全文删除、行尾删除、无末尾换行和上下文为 0 的情况。
7. 调整设置并重启，验证持久化；检查两个同文件编辑器之间不会串用光标。
8. 测试未跟踪文件、新纳入文件、重命名、冲突和外部 Git 变化。
9. 重新加载插件，确认自定义面板位置保留；禁用后检查标记、监听器和轮询已清理。

## 发布检查

1. 同步版本，执行上述自动化命令。
2. 确认源代码没有包含 vault、用户配置、依赖目录、临时库或密钥。
3. 使用与 `manifest.json` 完全一致的标签，不加 `v` 前缀。
4. 发布附件只需 `main.js`、`manifest.json`、`styles.css`，从干净构建中取得。
5. 下载 Release 附件并核对校验值；在测试 vault 中手动安装。
